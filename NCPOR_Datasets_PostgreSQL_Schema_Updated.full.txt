NCPOR Dataset Metadata
PostgreSQL Schema
Schema rebuilt from the supplied NCPOR NPDC dataset export
Source records analyzed:
 900 JSON records and 900 CSV rows. The supplied records expose NCPOR NPDC metadata
such as title, abstract, purpose, release information, scientific classification, project details, personnel, data center,
instrument, platform, location and resource links.
Design principle: preserve the source metadata faithfully, normalize repeated entities for relational querying, and retain the original raw
metadata in JSONB so fields that are sparse or added by NCPOR later are not lost.
1. What the supplied dataset actually contains
The export includes a source identifier, title, abstract, release date and URLs at the record level. A representative record
also contains structured Basic Information, Science Keywords, Project Details, Summary, Dataset Citation, Scientist Details,
Data Center, Instrument Details, Location, Platform and Data Set Progress.

Core table:
CREATE TABLE datasets 
    id UUID PRIMARY KEY DEFAULT gen_random_uuid,
    npdc_metadata_id VARCHAR64 UNIQUE NOT NULL,
    source VARCHAR150 NOT NULL,
    source_url TEXT,
    title TEXT NOT NULL,
    abstract TEXT,
    purpose TEXT,
    release_date DATE,
    data_set_progress VARCHAR50,
    data_set_language VARCHAR50,
    originating_center VARCHAR255,
    expedition_type VARCHAR30,
    expedition_year VARCHAR30,
    project_number VARCHAR100,
    project_name TEXT,
    series_name VARCHAR100,
    dataset_title TEXT,
    release_place VARCHAR255,
    version VARCHAR50,
    detail_url TEXT,
    xml_url TEXT,
    pdf_url TEXT,
    download_url TEXT,
    original_resource_url TEXT,
    raw_metadata JSONB,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now
;

    ON dataset_locationsregion, subregion;

    ON dataset_resourcesdataset_id;

    ON dataset_versionsdataset_id;

    ON dataset_embeddingsdataset_id;
-- HNSW index; tune vector dimension/model to the selected embedding model.
CREATE INDEX idx_dataset_embeddings_vector
    ON dataset_embeddings
    USING hnsw embedding vector_cosine_ops;
For pgvector, VECTOR1536 is only an example dimension. The production dimension must match the embedding model actually
selected by the team. If the embedding model changes, use a migration/versioning strategy rather than mixing incompatible vectors.

6. Source-data observations that affect the schema
The records are sparse: many top-level fields are null even though corresponding information appears in
raw_metadata/raw_text. For example, one supplied record has null values for fields such as science_category,
project_number and scientist_name at the top level, while the raw metadata contains the corresponding structured values.

8. Recommended relationship to the wider portal schema
This dataset model plugs into the previously designed portal through dataset_id relationships from publications, research
projects, expeditions, media and saved items. The dataset remains the authoritative metadata entity; binary files belong in
object storage, while PostgreSQL stores metadata, permissions, versions, provenance and searchable representations.
Important implementation note:
 keep the original NCPOR metadata payload. This gives the team a safe fallback when new
metadata fields appear and supports audit/provenance without redesigning the relational schema for every source-side change.
